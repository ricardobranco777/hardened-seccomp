| `delete_module` | Unloads a kernel module; no legitimate use in an application container. |
| `finit_module` | File-descriptor-based variant of init_module; same rationale. |
| `init_module` | Loads a kernel module; a direct host-compromise primitive with no legitimate use in an application container. |
| `ioperm` | Grants direct I/O port access; a hardware-level primitive with no legitimate use in an application container. |
| `iopl` | Grants direct I/O port access; a hardware-level primitive with no legitimate use in an application container. |
| `mount` | Mount manipulation is central to most container-breakout techniques. Ordinary application containers never need to call this themselves; the runtime handles mounts before the workload starts. |
| `perf_event_open` | Recurring source of Linux kernel privilege-escalation CVEs and a common Spectre-class side-channel primitive. Gated by CAP_SYS_ADMIN/CAP_PERFMON upstream; blocked outright here. |
| `process_vm_readv` | Same class of risk as ptrace: reads another process's memory directly. Blocked regardless of CAP_SYS_PTRACE. |
| `process_vm_writev` | Same class of risk as ptrace: writes another process's memory directly. Blocked regardless of CAP_SYS_PTRACE. |
| `ptrace` | Process-introspection primitive used to read/inject into sibling processes and steal credentials; blocking it regardless of CAP_SYS_PTRACE stops a debug-capability grant from doubling as an attack primitive. |
| `reboot` | Host/system power-management syscall with no legitimate use inside an application container. |
| `setns` | Namespace manipulation: lets a process join another namespace, another building block of breakout techniques. |
| `umount2` | Same rationale as mount: unmounting from inside the container is a breakout/tamper primitive, not an application need. |
| `unshare` | Namespace manipulation used to create new, less-confined namespaces from inside the container; a building block of several breakout techniques. |
